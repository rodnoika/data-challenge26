# TRAPS-V1 — синтетические пограничные диалоги

Создано с нуля 8 ноября 2026 года по замороженному DEFAULT_CHECKLIST. Тексты DEV не использовались как шаблоны; из data/dev.json прочитаны только типы полей и примеры timestamp. Это целевой стресс-тест правил; его результаты не являются оценкой точности на естественном распределении реальных обращений. Разметка сделана автором сценариев; независимой человеческой арбитражной проверки не было.

30 диалогов: RU 14 / KZ 8 / EN 8; 26 чатов и 4 звонка. Все реплики вымышлены; имена и проверочные данные заменены явными заглушками. audio_url=null у всех записей. Диалоги содержат от 6 до 11 реплик. Идентификаторы и целевые критерии не добавляются в текст разговора как подсказки модели. Факты интерфейса внутри сценария вымышлены и служат контекстом; сверка реальных тарифов не предполагается.

## Пограничная разметка до прогона

Спорные ячейки заранее исключены только в альтернативной метрике; полная метрика включает все 240 ячеек. Список зафиксирован до получения ответов модели и не подгоняется по промахам.

- trap-ru-09: c04.
- trap-ru-12: c04.
- trap-ru-13: c05.
- trap-ru-14: c05.
- trap-kz-03: c02.
- trap-kz-07: c03; c05.
- trap-en-06: c02; c07.

Причины споров: общая отсылка к специалистам допускает 0 или 5 для c04; временность настройки может быть несущественной (15 или 20); помощь с жалобой без отдельного признания неудобства допускает разные трактовки c05; этичность личной услуги отдельно от формальной вежливости спорна для c05; проверка личности адресата не легализует чужие данные (c03); новый вопрос после прощания ставит границу применимости c02 и c07. В trap-kz-03 идентификация запрошена но содержательная потребность изначально ясна: основной ответ c02=na; альтернативно запрос проверки можно считать уточнением.

c04 покрывает 0 / 5 / 10 / 15 / 20 / na; c06 покрывает 0 / 4 / 7 / 10. Флаг c08=yes есть в четырёх диалогах: преждевременное раскрытие статуса своего поручения; предложение личного перевода; раскрытие данных другого клиента; прямое оскорбление. Негативные контрпримеры: грубость клиента / официальная платная услуга компании / рабочий номер очереди.

## Воспроизведение

```powershell
npm test
npm run harness -- --data data/synthetic/traps-v1.json --labels data/labels/traps-v1-labels.csv --split all --with-calls
# RUN_JSON — путь JSON первого прогона из вывода harness; пересчёт без повторных API-вызовов
npm run harness -- --from RUN_JSON --labels data/labels/traps-v1-labels.csv --split all --disputed data/labels/traps-v1-disputed.csv
```

Флаг --with-calls нужен для всех 30 записей: без него существующий harness оценивает только 26 чатов. Метрику по 26 чатам следует сравнивать с приведённым пользователем DEV-ориентиром 94.4%; общая метрика на 30 дополнительно включает 4 звонка. Настройка default.samples в конфиге не используется harness автоматически: без --samples код берёт 1; на момент подготовки default.samples=1.
