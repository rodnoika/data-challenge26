## Выводы

1. **c02 — первая зона для проверки.** Два расхождения отражают разные ветви одного правила: модель расширила N/A на обрыв до запроса и предпочла N/A из-за полноты исходных данных несмотря на игнорирование вопроса. Это две наблюдаемые ошибки; данных для заявления о частоте систематического нарушения пока мало.
2. **c07 может проверяться по раннему прощанию вместо конца диалога.** В trap-en-06 модель сослалась только на [5] и не учла открытый вопрос [6]. Это важный риск даже когда итог и прощание формально присутствуют.
3. **На c04 остаётся граница между 0 и 5 для бесполезной отсылки к отделу.** Правильная передача с понятным следующим шагом распознана. Просто упоминание специалистов не стало ложными 20; расхождение затронуло только нижние ступени.
4. **Качество эталона ограничивает достоверность процента.** Вежливая формулировка не всегда означает клиентоориентированность; постороннее разглашение может одновременно нарушать ведение диалога. Три вероятные ошибки разметки показывают необходимость второго разметчика до использования набора как бенчмарка.
5. **Критические границы безопасности и языка на этом прогоне выдержаны.** Все четыре грубых нарушения найдены; ложных флагов на трёх контрпримерах нет; c01 и c03 совпали полностью. Для KZ результат не хуже EN. Масштаб проверки мал и каждая отдельная граница представлена немногими случаями.

## Предложения для будущей правки промпта — сейчас не применялись

- c02: задать явный порядок условий — сначала проверить игнорирование известных деталей; полнота запроса сама по себе не отменяет no. Отдельно согласовать с владельцем чек-листа ответ при обрыве до формулирования запроса; не добавлять новое условие N/A молча.
- c07: перед yes просматривать все реплики после последнего прощания; явно проверять новый незакрытый вопрос и то кто завершил соединение.
- c04: согласовать один короткий контрпример для 0 против 5: достаточно ли одного упоминания профильного отдела для «общей подсказки». Профильную передачу без следующего шага не считать автоматически 20.
- c05/c06: пояснить независимость критериев примерами. c08 не обнуляет другие оценки автоматически; при этом игнорирование замечания о чужих данных и посторонняя реплика могут иметь собственные основания для no и 7.
- Перед любым изменением провести независимый просмотр меток. Затем создать новую версию набора и проверять улучшения на ещё одном закрытом наборе; TRAPS-V1 после разбора уже нельзя считать неизвестным для настройки правил.
